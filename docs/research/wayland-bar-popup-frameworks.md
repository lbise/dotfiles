# Clickable Wayland bar widgets and popup menus

## Recommendation

Keep Waybar and Walker for now. Waybar already has a native GTK popup-menu facility, so a small static menu such as power, VPN, or a few launch actions does not need another shell. Its module click hooks can also open Walker for searchable, independent selection. This is the lowest-cost path for this repo's existing `waybar` and `walker` packages and configuration.

Choose Quickshell only when the menu is really an interactive panel: live device lists, sliders, per-application controls, keyboard navigation, shared state, and panel-to-panel coordination. It replaces Waybar as the bar implementation, but Walker can remain the application and clipboard launcher. Omarchy took that route.

## What each project can do

| Project | Fit for a clicked bar widget | Cost and limitation |
| --- | --- | --- |
| [Waybar](https://github.com/Alexays/Waybar) | Best incremental choice. Modules have `on-click` commands, and modules that implement `menu` can show a GTK menu defined in a GtkBuilder XML file, with actions mapped to commands. Groups can also reveal a drawer on hover or click. [Menu documentation](https://github.com/Alexays/Waybar/blob/4c495a41f6fe5689665783138ce0097f9b757e0a/man/waybar-menu.5.scd#L7-L106), [drawer documentation](https://github.com/Alexays/Waybar/blob/4c495a41f6fe5689665783138ce0097f9b757e0a/man/waybar.5.scd.in#L350-L420). | The native menu is a GTK menu with command actions, not a reusable reactive panel. A custom module can run any click command, but Waybar does not provide an application model, sliders, or a panel lifecycle. [Custom-module options](https://github.com/Alexays/Waybar/blob/4c495a41f6fe5689665783138ce0097f9b757e0a/man/waybar-custom.5.scd#L7-L130). |
| [Walker](https://github.com/abenz1267/walker) | A good command palette from a Waybar click. It has menu integration and dmenu mode, supports an exclusive provider query with `--provider`, and can run as a layer-shell surface. [Features and dependencies](https://github.com/abenz1267/walker/blob/42b3ed88abf50bc52638fb2835b7f17e3ea3ac4c/README.md#L7-L62), [provider flag](https://github.com/abenz1267/walker/blob/42b3ed88abf50bc52638fb2835b7f17e3ea3ac4c/src/main.rs#L250-L261), [layer-shell setup](https://github.com/abenz1267/walker/blob/42b3ed88abf50bc52638fb2835b7f17e3ea3ac4c/src/theme/mod.rs#L275-L314). | It is a launcher, not a bar-widget toolkit. It opens its own configured surface rather than a panel anchored to the clicked icon. |
| [Quickshell](https://github.com/quickshell-mirror/quickshell) | Strongest match for Omarchy-style work. QML `PanelWindow` creates an edge-anchored shell surface with exclusion zones. `PopupWindow` anchors a popup to an item or window, dismisses on outside click when `grabFocus` is enabled, and has placement adjustment. `IpcHandler` lets a click command control the already-running shell. [PanelWindow](https://github.com/quickshell-mirror/quickshell/blob/c6a516096dd84d5255b409482eb4bf740b952f88/src/window/panelinterface.hpp#L59-L126), [PopupWindow](https://github.com/quickshell-mirror/quickshell/blob/c6a516096dd84d5255b409482eb4bf740b952f88/src/window/popupwindow.hpp#L18-L106), [IPC](https://github.com/quickshell-mirror/quickshell/blob/c6a516096dd84d5255b409482eb4bf740b952f88/src/io/ipchandler.hpp#L91-L186). | A real shell program in QML and Qt. It asks this repo to own bar layout, services, focus, multi-monitor placement, and upgrades, instead of editing JSON and CSS. It is worth it for rich panels, not a four-item power menu. |
| [AGS](https://github.com/Aylur/ags) with [Astal](https://github.com/Aylur/astal) | A GTK desktop-shell route in TypeScript and GJS. AGS makes Astal windows and GTK widgets; its official simple-bar example uses `menubutton` and GTK `popover` for media, Wi-Fi, audio, battery, and a calendar. Astal supplies libraries for common desktop services such as NetworkManager, PipeWire, MPRIS, Hyprland, and tray items. [AGS quick start](https://github.com/Aylur/ags/blob/bbee2f18939f1ec7ff720e717cf305e73635628f/docs/guide/quick-start.md#L1-L67), [bar and popover example](https://github.com/Aylur/ags/blob/bbee2f18939f1ec7ff720e717cf305e73635628f/examples/gtk4/simple-bar/Bar.tsx#L17-L258), [Astal libraries](https://github.com/Aylur/astal/blob/e07013e6104f852b2e6802d3d9a30e73c4bca4b7/docs/guide/libraries/references.md#L5-L48). | A complete Waybar replacement with a TypeScript, GJS, GTK, Astal, and Gnim toolchain. The official docs explicitly use GTK4 `Popover` for a popup. [AGS popup guidance](https://github.com/Aylur/ags/blob/bbee2f18939f1ec7ff720e717cf305e73635628f/docs/guide/faq.md#L259-L273). Good if the user prefers TypeScript and GTK over QML, but a large change for these dotfiles. |
| [Eww](https://github.com/elkowar/eww) | Declarative GTK widgets in Yuck and CSS/SCSS. `defwindow` can create a bar or a separately opened panel, with Wayland stacking, focus mode, namespace, geometry, and automatic close when it loses keyboard focus. [Configuration](https://github.com/elkowar/eww/blob/48f5aa8b379adf29da0b0bb9ca04164f65d8bdaa/docs/src/configuration.md#L1-L96), [Wayland build and daemon commands](https://github.com/elkowar/eww/blob/48f5aa8b379adf29da0b0bb9ca04164f65d8bdaa/docs/src/eww.md#L20-L80). | Good for a custom bar plus dashboard-style windows. Anchor placement is declared as window geometry, not automatically tied to the clicked child, so an icon-specific popup takes more manual geometry and state wiring than Quickshell or GTK `Popover`. It would replace Waybar for the widgets it owns. |
| [gtk4-layer-shell](https://github.com/wmww/gtk4-layer-shell) | A low-level building block for a GTK application in C, Python, Rust bindings, Vala, or GJS. It implements layer-shell windows that can anchor to output edges and reserve space. GTK can provide a `Popover` or `MenuButton` inside that bar. [Project README](https://github.com/wmww/gtk4-layer-shell/blob/e08cf8776969327849e1f28ad44d72bc038122c5/README.md#L5-L13), [minimal anchored bar](https://github.com/wmww/gtk4-layer-shell/blob/e08cf8776969327849e1f28ad44d72bc038122c5/examples/simple-example.c#L14-L41). | Not a bar framework. It leaves data sources, rendering, configuration, IPC, and popup behavior to the application. Use it only when writing and maintaining a small purpose-built GTK program is preferable to Eww, AGS, or Quickshell. |

## Current Omarchy implementation

This section inspected local Omarchy checkout [`b5589fa`](https://github.com/basecamp/omarchy/tree/b5589faaf80c6f87c07d4560fca37c4a81722f28), not the older Waybar-based releases.

Omarchy now starts `omarchy-launch-shell` from Hyprland startup. That launcher runs one long-lived Quickshell instance on `shell/`. [Autostart](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/default/hypr/autostart.lua#L1-L13), [launcher](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/bin/omarchy-launch-shell#L17-L20), [shell overview](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/README.md#L1-L24). It does not use Waybar or Walker for this UI.

- The bar is a Quickshell `PanelWindow`, one per screen, with a layer-shell top layer. Its layout comes from `~/.config/omarchy/shell.json`; the shipped layout includes the menu, workspaces, clock, tray, Bluetooth, network, audio, monitor, and power widgets. [Bar surface](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/plugins/bar/Bar.qml#L648-L704), [default layout](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/config/omarchy/shell.json#L7-L68).
- The menu icon is a bar widget. Left-click sends an IPC toggle to `omarchy.menu`; the `menu` plugin renders a keyboard-focused, full-screen overlay with a centered card, rather than a small icon-anchored menu. Menu rows come from shipped and user JSONC definitions. [Menu button](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/plugins/menu/BarWidget.qml#L1-L22), [menu manifest](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/plugins/menu/manifest.json#L1-L22), [overlay surface](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/plugins/menu/Menu.qml#L1027-L1067).
- Rich status widgets are plugins, not fixed Waybar modules. For example, `omarchy.audio` uses a bar icon and a `KeyboardPanel` containing sliders, output and input pickers, and per-app streams. The panel is a full-screen layer-shell overlay that positions a card beside the icon, coordinates one open popout, dismisses outside clicks, and briefly takes keyboard focus so hotkey-opened panels work. [Audio widget](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/plugins/panels/audio/Panel.qml#L397-L447), [keyboard panel](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/Ui/KeyboardPanel.qml#L1-L94), [plugin model](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/docs/omarchy-shell.md#L8-L40).
- Omarchy also has a reusable `PopupWindow` card for simpler pointer-driven popouts. It calculates placement from the bar edge and anchor item, clamps it to the screen, and uses a Hyprland focus grab for click-outside dismissal. [Popup card](https://github.com/basecamp/omarchy/blob/b5589faaf80c6f87c07d4560fca37c4a81722f28/shell/Ui/PopupCard.qml#L1-L138).

The important distinction is easy to miss: Omarchy's main command menu is an overlay, while its audio, network, power, and similar widgets are icon-positioned panels. The polished result comes from the shared shell and its popup coordinator, not from a special Waybar configuration.

## Practical path for these dotfiles

1. For a static context menu, add a Waybar `menu`, `menu-file`, and `menu-actions` to an existing or `custom/*` module. Keep the action commands in this repo. This preserves the present bar and needs no service.
2. For a searchable chooser, have Waybar run Walker with a narrow provider or a Walker/Elephant custom menu. Walker is already installed and configured here, including the clipboard provider prefix. It is suitable when anchored placement is not important.
3. Do not add Eww, AGS, or raw GTK layer-shell beside Waybar for one menu. That creates a second UI runtime without removing the first.
4. If several modules need live interactive panels, replace Waybar deliberately with Quickshell or AGS. Keep Walker as the launcher during that migration. Quickshell is the closer technical match to current Omarchy. AGS plus Astal is the better fit only if TypeScript and GTK are a clear preference.

All findings above use owner repositories and the local Omarchy source only.
